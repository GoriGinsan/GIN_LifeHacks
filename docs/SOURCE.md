# Source guide

All three plugins target Koikatsu CharaStudio, BepInEx 5 and the game's .NET 3.5-era runtime. Build with `src/build.ps1`; the .NET SDK is not a game runtime dependency.

## Shared

`src/Shared` is compiled into every plugin by `build.ps1`, so each DLL carries its own copy and none depends on another.

| File | Responsibility |
| --- | --- |
| `EndlessDrag.cs` | Drags that go on beyond the screen edge: the cursor is hidden and parked in the middle of the game's screen, the mouse's own movement (Unity's mouse axes) is used at the speed measured from the cursor's free movement, and the cursor returns on release. Used by the Pad's bars, drag buttons (the time button included) and Body figure, and the Advanced helper's scrub buttons. The Timeline helper does not use it and is built without it |

## Timeline

Start with `src/Timeline/Plugin.cs` for state, settings and the Unity update loop.

The Timeline helper has two editions. `build.ps1` builds both by default: the private one (`bin`, compiled with `CHAR_SETUP`) and the public one for distribution (`bin/public`), which leaves out Char Setup because it crashed the game on some installations. The public edition is compiled without `CharacterSetup.cs`, `SetupObjects.cs`, `SetupThemes.cs`, `Diagnostics/WorkflowVerification.cs` and the embedded `CharacterSetup.xml` (the list is `$charSetupSources` in `build.ps1`); the few remaining references are under `#if CHAR_SETUP`.

| File | Responsibility |
| --- | --- |
| `Attachment.cs` | Attach to native Timeline and restore owned changes on detach |
| `NativeReflection.cs`, `Compatibility.cs` | Cached native member access, Harmony callbacks and supported API contracts |
| `Companions.cs` | Cached lookups of optional neighbours: GIN Advance, KKPE, ConfigurationManager |
| `Layout.cs`, `ToolbarPlacement.cs` | UI elements and placement around the resize handle and screen edges |
| `CandidatePanel.cs` | Right-side Interpolables browser and original row restoration |
| `Input.cs`, `InputFocus.cs`, `PointerHooks.cs` | Shortcut routing, typing protection and native pointer hooks |
| `KeySelection.cs` | Current-value updates, anchor and alternating key selection |
| `Groups.cs`, `GroupInteraction.cs` | Group summaries, selection, drag previews and native commits |
| `CameraGuard.cs` | Preserve camera input conditions while interacting with added UI |
| `TrackRegistration.cs` | Bulk row registration from a template in Timeline's own XML shape; fills only missing rows |
| `CharacterSetup.cs`, `CharacterSetup.xml` | Char Setup: the template (generated by `src/tools/extract_character_setup.py` from a setup scene, embedded in the DLL) and its rows |
| `SetupObjects.cs` | Char Setup: the items and folders around the character (Sideloader lookup, sizes, colours, Material Editor) and the NodesConstraints links |
| `SetupThemes.cs` | Char Setup: one row colour theme per character |
| `AutoKey.cs` | Auto Key: how a manual edit is told apart from playback, animation and blinking |
| `AutoKeyButton.cs` | The Auto Key record button, its curve menu and the generated icons; the curve of keys Auto Key adds |
| `FaceRows.cs` | Services for GIN Pad life hack: whole-face key, keys for rows of named bones / guide objects / renderers, and which Blend Shapes the keys use |
| `KeyDelay.cs` | Delay Key for GIN Pad life hack: keys of the body parts the Pad edits written a part's delay after the playhead (Auto Key, Key now) |

## Advanced mode

Start with `src/Advanced/Plugin.cs` for settings and lifecycle. `AdvancedUi.cs` owns the adapter state and patch installation. Its partial files keep the same runtime class while separating styles, Blend Shape visibility, bone controls, transpilers and display templates.

`AdvancedUi.TimelineRows.cs` adds the Blend Shapes "Timeline 0:00" buttons. It builds a template and hands it to `GinTimelineHack.Plugin.RegisterTracksFromXml` through reflection; neither plugin references the other at compile time.

`ExpressionData.cs` defines the existing XML data and storage helpers. `ExpressionRuntime.cs` captures and applies native character values. `ExpressionLibrary.cs` manages the library and storage; `ExpressionLibrary.Drawing.cs` draws it. `NativeReflection.cs` contains the shared `ReflectionAccess` helper.

## Pad

`src/Pad` is the third plugin, GIN Pad life hack. Start with `Plugin.cs` (settings, toolbar button, Unity callbacks).

| File | Responsibility |
| --- | --- |
| `Kkpe.cs` | The selected character (or an item, for its Blend Shapes) and everything read from or written to KKPE: Blend Shape overrides with the eye link, bone overrides (also read and restored whole for Undo), FK / IK lookups, limb copy, switching KKPE on for an item |
| `Reflect.cs` | Cached reflection used by `Kkpe.cs` and the toolbar |
| `PadUi.cs` | Scaled sizes (`Px`, `Width`), solid button styles, the drag bars (bounded `Bar`, unbounded `DeltaBar`), the drag buttons of the Move tab and the middle-click key request |
| `PadWindow.cs` | Window shell: character or item tabs by Studio's selection, open tabs side by side, auto-fit, translucent background, middle-click keys per tab, remembered settings |
| `PadWindow.Corners.cs` | Controls outside the window's top corners: play / pause and the time drag with its large readout (top left), the resize knob that scales the whole window (top right); what counts as the window for the input guards; keeping the window on screen |
| `PadWindow.Face.cs` | Face tab: which Blend Shapes are listed (`Fav` / `Used` / `All`), pinned shapes |
| `PadWindow.Pupils.cs` | The pupils: gaze on the Map (right drag), limits and depth |
| `PadWindow.Map.cs`, `ExpressionMap.cs` | Map tab and its data: pose lists, blending, file format; Shift axis lock; brows and pupil bars below the map |
| `PadWindow.MapMaking.cs` | The Map's pose editor: the triangles, the bars beside the map, reorder / add / delete / undo, autosave. Changes to the pose lists are requested by GUI events and carried out in `Update` |
| `DefaultExpressionMap.cs` | Generated by `src/tools/map_file_to_default.py` from the author's own map (or by `learn_expression_map.py` from scenes); do not edit by hand |
| `PadWindow.Body.cs` | Body tab: the figure, multi-selection, drags on buttons (with per-bone axis limits), IK and bone bars, limb copy, Key now, when a press's Undo step is made; the Shapes tab (body Blend Shapes) |
| `PadWindow.Delay.cs` | Delay Key: each body part's delay in seconds, the delay bar beside the figure (marks, stretch, zoom, typing), the figure's Edit mode, dragging a part with the parts beyond it from the origin, the large readout |
| `PoseUndo.cs` | Studio's Undo for the Body tab: a snapshot of the pose (IK targets, FK nodes, KKPE's bone overrides), the step made from two snapshots, and KKPE's own step folded into it |
| `ItemSelection.cs` | Item mode's view of Studio's selection, FK node stepping with the wheel (`FkWalk`) and the Undo command for moves and turns |
| `PadWindow.Items.cs` | Item tabs: Move (Move Controller's square, turns, To camera, Anim, Reset FK, wheel) and the item's Shapes |
| `TimelineBridge.cs` | Optional calls into the Timeline plugin (whole-face key, named-row keys, shape usage) |
| `InputGuard.cs` | Keeps clicks, gizmo drags and camera input on the window away from Studio: a postfix on `EventSystem.RaycastAll` answers "the Pad window" while the pointer is on it. The camera part is a Harmony prefix on `Studio.CameraControl`, because Studio appends its own entry to the camera's `noCtrlCondition` delegate and only the last entry's answer counts |
| `ToolbarIcon.png` | 32 x 32 toolbar icon, embedded in the DLL by `build.ps1` |

One IMGUI rule shapes `PadWindow`: a click may only *request* a change of what is shown (tab, selected part, message). The next Layout pass adopts it (`shown...` fields), so Layout and the following event always see the same controls.

## Compatibility rules

- Keep plugin GUIDs, configuration section/key names and saved XML identities stable.
- Retain native method/field names used by Harmony and reflection. Small changes to those strings can break attachment or input routing.
- Keep partial-class field initializers in their original files and order; method files may be separated without moving startup state.
- Do not add GIN-only scene providers for native Timeline keys or KKPE values. New rows are created by the native providers (`InterpolableModel`), exactly as the native scene loader does.
- The plugin version lives in one place: `Plugin.Version` in each `Plugin.cs`. `package.py` reads it.
- Compile against local game assemblies without redistributing them. Keep installed DLL filenames fixed.

Each plugin's `Diagnostics/` folder contains guarded regression entry points. They require the explicit verification launch flag and a marked disposable game. They do not run during normal use. See [verification](VERIFICATION.md) for runtime coverage and limits.
